# Dynamic artwork research and implementation plan

This is the preserved pre-implementation research record. The provider integration, private token setup and phone verification now exist; see [ARTWORK-IMPLEMENTATION.md](ARTWORK-IMPLEMENTATION.md). Statements below about missing credentials or providers describe the earlier investigation.

## Scope and original Premiere path

This is a design/retrieval investigation only. No provider is wired into the APK, and no credentials are present. The current renderer is `Premiere.UI.art(Object, int)` in `native/org/videolan/vlc/premiere/Premiere.java` (around line 1008). Its lookup order is VLC `getArtworkMrl()` (local art only), embedded media art via `MediaMetadataRetriever.getEmbeddedPicture()`, then a sampled video frame at one second. Artwork is displayed from the in-memory `cache`, keyed now by artwork MRL or media URI. Keep embedded album art and existing identified cover/poster art first. For videos, a sampled frame remains a temporary/failure fallback: it must not suppress an online poster lookup, otherwise almost every movie would stay a frame thumbnail.

The existing bridge references and decoded app sources establish exact metadata access points:

- `MediaWrapper`: `getTitle()`, `getFileName()`, `getUri()`, `getDate()`, `getArtist()`, `getAlbum()`, `getArtworkMrl()`, `getTrackID()`, `getTrackNumber()`, `getType()`, `getWidth()`, `getHeight()`. `Premiere` also currently calls `getArtistName()`.
- `Medialibrary`: `getVideos()`, `getAudio()`, `getMediaCb` registration via `addMediaCb(...)` / `removeMediaCb(...)`, plus `discover(String)` and `reload(...)`.
- `Medialibrary.MediaCb`: `onMediaAdded()`, `onMediaDeleted(long[])`, `onMediaModified()`, `onMediaConvertedToExternal(long[])`. `onMediaAdded()` has no IDs, so reconcile from the library query; deletion has IDs. The callback source is `work/smali_classes5/org/videolan/medialibrary/interfaces/Medialibrary$MediaCb.smali`.
- Folder scan inclusion/removal is surfaced in Premiere's folder actions through `MedialibraryUtils` (`Premiere.java` around 1367–1428 and 1502–1535). Rescan after successful inclusion/removal; it is separate from media added/deleted callbacks.

**Integration point recommendation (inference):** Add a provider-neutral resolver alongside `art()`. Display local embedded/identified art or a frame immediately, while missing posters resolve in a separate paced network queue; replace a frame when a confident poster arrives. Decode/cache downloaded images on the image executor and post to the main handler only if the media identity and view tag still match. The callback-aware reconciliation belongs alongside UI/library lifecycle setup, not in the row renderer. Persist image bytes and a small lookup manifest under app-private cache; keep a bounded memory cache for display. A poster should be selected only after a strong, unambiguous match. Expose an explicit provider/attribution setting and do not silently enable a provider before its terms and product use category have been reviewed.

## Provider behavior grounded in primary docs

### Movies and TV: TMDB

- TMDB provides dedicated movie and TV title search endpoints and image metadata; use `/search/movie` for movies and `/search/tv` for series, then retrieve detail/images for the selected result. Start with the [official search and query guide](https://developer.themoviedb.org/docs/search-and-query-for-details), [movie search reference](https://developer.themoviedb.org/reference/search-movie), [TV search reference](https://developer.themoviedb.org/reference/search-tv), and [image basics](https://developer.themoviedb.org/docs/image-basics). Its image URL construction uses configuration (base URL and permitted sizes) plus the returned image path; do not guess URL forms.
- **Credentials:** Application API access requires registering for a TMDB API key and agreeing to its terms; see [getting started](https://developer.themoviedb.org/docs/getting-started). App/user session credentials are for user-account actions and are not needed for simple search. The docs support API key or application bearer token auth; no key has been supplied, so this prototype performs no API call and no no-key TMDB assumption is made.
- **Rate limit:** TMDB says its former fixed limit was disabled, asks clients to respect `429`, and says the limit can change; do not encode an assumed requests-per-second contract. See [rate limiting](https://developer.themoviedb.org/docs/rate-limiting). Proposed client policy: one in-flight metadata request per provider, small bounded queue, deduplicate by normalized query, exponential backoff with jitter for 429/5xx, and pause on repeated failures. These concurrency details are app policy, not TMDB guarantees.
- **Attribution / use:** TMDB documents free API use for non-commercial purposes with attribution, including TMDB logo and notice, placed in an About/Credits section; commercial use requires contacting TMDB for a license. See [official FAQ](https://developer.themoviedb.org/docs/faq) and [logos and attribution](https://developer.themoviedb.org/docs/logos-and-attribution). This personal rebuild fits the proposed non-commercial path; broader commercial distribution would require the corresponding license. The FAQ says TMDB does not claim ownership of API images/data; that does not eliminate third-party rights or other terms.
- **Caching:** The [API terms](https://www.themoviedb.org/api-terms-of-use) prohibit keeping TMDB content longer than six months. Use a shorter hard expiry (for example 90 days), bounded app-private cache, and purge expired images/metadata even while offline. The terms were accessible through the official indexed page; direct page access was blocked by robots, so confirm the current terms when registering the key.

### Music metadata and cover art: MusicBrainz + Cover Art Archive

- MusicBrainz is metadata discovery, not the image host. Search the `release-group` index using tag metadata first (`artist` + `release`/album title) and consume IDs/date/title/artist credit; official API docs describe the [Web Service](https://musicbrainz.org/doc/MusicBrainz_API), [search syntax and release-group fields](https://musicbrainz.org/doc/MusicBrainz_API/Search), and [rate limiting](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting).
- **Credentials:** Public metadata search does not require an API key/account auth. MusicBrainz does require a descriptive, contactable `User-Agent` with product and version. `Java` / blank generic clients are explicitly anonymous and discouraged. Auth is needed for user-specific/private operations, not public search.
- **Quota:** The rate-limit page documents a current average source-IP ceiling of 1 request/second, with throttling returning 503; it says limits may change. Put all MusicBrainz work behind a shared process-wide limiter at <=1 request/second (including retries), obey 503/backoff, and avoid per-file fan-out. This is essential because all users behind one NAT may share the provider-observed source IP; exact shared traffic behavior is an inference from the IP policy.
- Cover images are indexed by MusicBrainz release ID at the [Cover Art Archive API](https://musicbrainz.org/doc/Cover_Art_Archive/API), with `/release/{mbid}` and `/release-group/{mbid}` JSON endpoints and front/thumbnail routes. The docs state the API is at `coverartarchive.org`, artwork is community-curated and hosted through redirects to Internet Archive; there is no API key described. The CAA page currently says it has no rate-limiting rules, while endpoints can still return 503 when rate-limited; treat this as changeable, use low concurrency and retry conservatively.
- **Rights / attribution / cache:** CAA describes an archival collection, says to respect artist/label rights, and links the Internet Archive policy. This is not a blanket copyright license. Keep the MusicBrainz release link/CAA provenance with cache metadata and review the [CAA policy](https://musicbrainz.org/doc/Cover_Art_Archive) and linked [Internet Archive terms](https://archive.org/about/terms.php) before redistribution. No official retention period was found in these docs; use bounded disposable cache and do not re-upload or redistribute art.

## Matching and privacy design

1. **Metadata first, local only.** Prefer Medialibrary title and artist/album objects plus actual release-year tags extracted from the media; validate the semantic meaning of `getDate()` (a string field), and do not treat file-modified/added timestamps as release years. Use tags extracted from the media (`MediaMetadataRetriever` on Android; `ffprobe` in the research probe). Only then use the filename. For audio, search MusicBrainz with artist + album/release and fetch the CAA release-group front. Track title alone is too ambiguous. If album tags are absent, optionally resolve artist/recording through MusicBrainz first, then consider candidate releases; keep a fallback if the recording belongs to several albums. For video, select movie versus TV based on `SxxExx` / media type, then query TMDB by cleaned title and year; TV episode season/episode can further narrow series details.
2. **Filename normalization.** Strip extension, release-group suffixes (`-ETHEL`, `[YTS.BZ]`), bracketed annotations, resolution (`1080p`, `2160p`, dimensions), source (`WEB-DL`, `WEBRip`, `BluRay`, `HDTV`), codec (`x264`, `H.264`, `HEVC`, `AV1`), audio tags (`AAC5.1`, `DDP5.1`, `DTS-HD`), and quality markers (`HDR`, `IMAX`, `PROPER`, `REPACK`, `REMUX`). Detect and remove a standalone year while retaining it as a constraint. Detect `SxxEyy` before stripping separators and retain season/episode. Never drop meaningful dotted title tokens just because they are separated with periods.
3. **Conservative score (proposed, not provider contract).** Normalize Unicode/case/punctuation; compare token Jaccard plus normalized edit similarity, with title exact/token score weighted most. Give strong weight to exact year and exact artist for music, and use season/episode only to confirm series identity. Reject known year conflicts for movies. Album reissue years may differ from original release dates, so use artist/album identity rather than blindly rejecting a music year mismatch. If movie year is absent, require substantially stronger title evidence. Require a high threshold (e.g. >=0.90) and a meaningful lead over runner-up (e.g. >=0.12); these are starting thresholds to validate on a library, not scientifically calibrated constants. If not unique, preserve current embedded/frame fallback and offer manual resolution later. Never auto-select a weak “best available” candidate.
4. **Do not disclose private paths.** Provider requests contain only normalized title/year or artist/release metadata. Never send file URI, basename with release group, directory, storage volume, or path. The research command operates offline and prints local paths only to its terminal; no HTTP/client library exists in the prototype.

## Cache, queue, and storage lifecycle (proposed)

- Cache identity should be `SHA-256(provider + normalized metadata identity + content identity)`, where content identity includes a stable media-library ID/URI locally, file size and last-modified timestamp (or a content fingerprint if stable URI metadata is unavailable), plus current title/artist/album/date. The key never needs to be transmitted. Store downloaded image bytes and a manifest with provider entity ID, selected image URL, ETag/Last-Modified when present, fetch time, attribution/provenance, and source metadata. Current `Premiere.cache` keyed only by MRL/URI is in-memory and can become stale after file edits; disk cache should be versioned separately.
- Use bounded app-private cache with LRU/size ceiling and TTL for misses (shorter than successful art). Honor HTTP cache headers where available; refresh only when stale, never re-fetch on each bind. Clean orphan entries when media disappears or scan roots are removed. Keep cache under app cache storage, not the user's media folders.
- Treat an unmounted or permission-blocked scan root as temporarily unavailable, rather than deleting all of its cached identities as though the user removed the files. Reconcile only after a successful scan; use bounded cache expiry for orphan cleanup.
- Queue only visible/missing-art items or a small paced background batch. Deduplicate requests sharing normalized metadata. Bound worker count (e.g. 1–2 globally), use per-provider rate gates (MusicBrainz <=1 req/s; TMDB adaptive and respect 429), connect/read timeouts, cancellation tokens, and discard late results after view reuse, item deletion, or query change. A lookup for a scrolling-away card should be cancelable before network start.
- On `onMediaAdded` / `onMediaModified`, re-query and reconcile current videos/audio. On `onMediaDeleted(ids)`, purge mapping/cache records for those library IDs after confirming the ID accessor exposed by the shipped wrapper (the bridge extraction should be extended before implementation). On `onMediaConvertedToExternal(ids)`, reconcile changed entries. After add/remove of scanned roots, reconcile the full library; removed roots may produce delete callbacks, but do not assume callback completeness. Also run a lightweight reconciliation at app startup/rescan to detect filesystem changes not reflected by callbacks. For each current URI/path compare size + modified time; changed identity invalidates cache, removed files purge mapping, new files enqueue lazily. SAF content URIs may not expose size/mtime consistently, so use available document metadata plus MediaWrapper fields and invalidate conservatively.

## Local proof script

`research/artwork_probe.py` recursively scans a directory chosen at runtime, calls installed `ffprobe` for media tags, falls back to normalized names, and emits JSON candidates and local cache identity hashes. It has no network code. Re-running after files are added/removed/changed changes the output set/identity; a future watch loop can use filesystem events plus periodic reconciliation, but this probe deliberately rescans on each invocation for portable behavior. `research/test_artwork_probe.py` exercises filename/tag extraction, album lookup identity, Unicode, ambiguous matches, and storage add/change/remove behavior without a key. Five fixture tests pass. The probe was also run on two actual local video files with ffprobe; this validates metadata extraction, not provider match accuracy. The probe emits an album/artist lookup separately from the retained track title; missing album/artist yields no online music query.

Run from repository root:

```sh
python3 -m unittest discover -s android-premiere/research -p 'test_*.py' -v
python3 android-premiere/research/artwork_probe.py /path/chosen/by/user
```

The script is a parsing/cache-identity proof only. It does not fetch providers, inspect VLC's database, guarantee fuzzy-match accuracy, implement Android cache lifecycle, or prove phone integration.

## Premiere poster presentation (proposed, not implemented)

Keep Premiere’s selected palette, typography and navigation. Build portrait movie/series cards (2:3) from the current scanned library, with title/year and resume progress below or over the poster. Recently added and Continue watching shelves derive from local library timestamps/history, not a fixed catalogue. Use square album cards (1:1) for music. Group episodes by matched series while retaining the actual local episode files and VLC playback actions. A failed/ambiguous lookup keeps a local thumbnail and title; a poster never determines whether a file can play. Offline browsing uses valid cached artwork and the storage library. Removing a file removes its card on reconciliation, even if its poster remains shared by another local file.

## Concrete implementation prerequisites

TMDB needs an application key or read token, stored through an app setting/local configuration (never a checked-in secret). Public MusicBrainz/CAA retrieval needs no API key but does need a descriptive application User-Agent and the one-request-per-second MusicBrainz queue. Online lookups send only normalized title/year or album/artist; files and storage paths stay local. No provider queries or downloads were performed in this investigation. The APK currently contains no network poster resolver, disk artwork cache, or portrait poster shelves.
